# grin-ffi JSON contract

This is the data contract between `packages/grin/rust` and the Dart package
`packages/grin`. The C signatures are in `packages/grin/rust/include/grin_ffi.h`
(generated by cbindgen, committed) and in docs/architecture.md section 4.6.
This document covers what goes inside the strings.

## 1. Conventions

### 1.1 Result struct

Every function except the three `void` ones returns:

```c
typedef struct GrinFfiResult {
  int32_t code;   /* 0 on success, otherwise a GrinErrorCode */
  char   *data;   /* success: JSON text, or NULL when there is nothing to return */
  char   *error;  /* failure: error JSON (section 2), otherwise NULL */
} GrinFfiResult;
```

- On success `code == 0`, `error == NULL`, and `data` is either a JSON document
  or NULL. Functions documented as returning "nothing" always give NULL.
- On failure `code != 0`, `data == NULL`, and `error` is the error JSON.
- Free every result exactly once with `grin_ffi_result_free(res)`. It zeroes
  both strings before freeing them (results can hold a mnemonic).
  `grin_string_free(ptr)` frees a single string from this library. Both accept
  NULL members.
- The `void` functions are `grin_ffi_result_free`, `grin_string_free` and
  `grin_wallet_close_finalizer`. They never fail and never unwind.

### 1.2 Arguments

- `const char *` arguments are NUL-terminated UTF-8. Invalid UTF-8 gives
  `InvalidUtf8` (2).
- A NULL pointer gives `InvalidArgument` (1) unless the argument is listed as
  nullable below.
- For nullable `api_secret` and `socks_proxy` arguments, an empty string is
  treated the same as NULL.
- Passwords and mnemonics are copied into zeroing buffers on entry and never
  logged. The caller still owns (and should zero) its own copy.
- `network: u8` is `0` Mainnet, `1` Testnet (Floonet), `2` UserTesting,
  `3` AutomatedTesting. Anything else is `InvalidArgument`. This numbering is
  our own and does not follow the order of `ChainTypes` in grin_core.

### 1.3 Panics, threads and chain type

- Every body runs inside `catch_unwind`. A Rust panic becomes
  `InternalPanic` (16) with the panic message in `message`.
- Calls are synchronous and may be made from any thread. There is no
  process-wide chain type: each call sets the calling thread's chain type
  from its `network` argument, its config, or the wallet behind its handle.
  A Mainnet and a Testnet wallet can be used at the same time from the same
  threads.
- Handles are non-zero `u64` values, never reused within a process. `0` and
  unknown values give `InvalidHandle` (7).

### 1.4 Numbers

All amounts are `u64` nanogrin (1 grin = 1,000,000,000 nanogrin) written as
JSON integers. Heights are `u64` integers. Nothing is a float or a decimal
string.

## 2. Errors

### 2.1 Error JSON

```json
{"code": 18, "message": "the wallet directory is in use by an open or still closing wallet", "details": {"wallet_dir": "/data/w/wallet_data"}}
```

| Field | Type | Meaning |
|---|---|---|
| `code` | integer | Same value as `GrinFfiResult.code`. |
| `message` | string | Human-readable English text. Not stable; do not parse it. |
| `details` | object or null | Structured data for some codes, listed below. |

### 2.2 Codes

Values are append-only; Dart maps them by number.

| Code | Name | Meaning | `details` |
|---:|---|---|---|
| 0 | `Ok` | Success. Never appears in an error JSON. | |
| 1 | `InvalidArgument` | NULL where not allowed, out-of-range value, bad URL or proxy, handle for another directory. | null |
| 2 | `InvalidUtf8` | A string argument is not valid UTF-8. | null |
| 3 | `Json` | A JSON argument does not parse or misses a required key. | null |
| 4 | `WalletNotFound` | No `wallet_data` directory or no `wallet.seed` in it. | `{"wallet_dir": string}` (as given) from create, open and delete; null when `wallet.seed` disappeared under an open wallet |
| 5 | `InvalidPassword` | The password does not decrypt `wallet.seed`. Only returned when the seed file is present and well formed, so it never stands for a damaged or unreadable file or a failed write. | null |
| 6 | `WalletExists` | `grin_wallet_create` on a directory that already has `wallet.seed`, or that has leftover wallet data (`db/` or an LMDB file) without one. | `{"wallet_dir": string}` (as given); for leftover data also `"reason": "leftover_wallet_data"` and `"path"` (what was found, relative to `wallet_data`) |
| 7 | `InvalidHandle` | Handle is 0, unknown, or already closed. | null |
| 8 | `Lifecycle` | Other wallet open/close/seed failures from the lifecycle provider, including a damaged `wallet.seed` and a password change that failed after the old password was verified. | null; for a failed password change `{"seed_present": bool, "backup_file": string or null}` |
| 9 | `Node` | The node could not be reached or gave an unusable answer, including a failed broadcast and a cancel that could not refresh first. | null, or `{"slate_id"}` (section 9.1) |
| 10 | `InsufficientFunds` | Not enough spendable funds. | `{"required": u64, "available": u64}` |
| 11 | `Slate` | Slate or Slatepack could not be parsed, encrypted, decrypted or is in the wrong state. | null, or `{"slate_id"}` (section 9.1) |
| 12 | `Transaction` | Transaction building or bookkeeping failed, or a payment proof does not verify. | null, or `{"slate_id"}` (section 9.1) |
| 13 | `NotFound` | Transaction, stored finalized transaction or payment proof does not exist. | null, or `{"slate_id"}` (section 9.1) |
| 14 | `Cancelled` | A running scan was stopped between batches by `grin_wallet_scan_cancel` or by closing the wallet. | `{"scanned_height": u64, "tip_height": u64}`, or null when the handle was closed before the scan started |
| 15 | `Io` | File system error. | null |
| 16 | `InternalPanic` | A Rust panic was caught. | null |
| 17 | `Internal` | Unexpected internal error. | null |
| 18 | `WalletBusy` | The wallet directory is held by an open wallet or one still closing, or a scan is already running. | `{"wallet_dir": string}` (canonical path of `wallet_data` itself, not the `wallet_dir` that was passed); for a running scan also `"reason": "scan_in_progress"` |
| 19 | `Http` | Wallet-to-wallet HTTP communication failed, or the other wallet refused the slate. | null |
| 20 | `NotSupported` | The function is not implemented in this build. | null |
| 21 | `InvalidAddress` | Not a valid slatepack address, onion address or URL, or a slatepack address for the other network. | null |
| 22 | `InvalidMnemonic` | Mnemonic has a word outside the BIP39 English list, a bad checksum, or a bad length. The message never repeats the words. | null |

## 3. Wallet config (`config_json`)

Used by `grin_wallet_create` and `grin_wallet_open`.

```json
{
  "wallet_dir": "/data/user/0/app/files/grin/main",
  "network": 0,
  "node_url": "https://grinnode.example.com:3413",
  "node_api_secret": null,
  "socks_proxy": "127.0.0.1:9050",
  "request_timeout_secs": 30
}
```

| Key | Type | Required | Notes |
|---|---|---|---|
| `wallet_dir` | string | yes | Must not be empty. Wallet files live in `<wallet_dir>/wallet_data` (`wallet.seed`, `db/`, `saved_txs/`, `tx_metadata.json`). Nothing else in `wallet_dir` is touched. |
| `network` | u8 | yes | See 1.2. |
| `node_url` | string | yes | `http://` or `https://` base URL of a node's API. A trailing `/` is removed; `/v2/foreign` is appended internally. Credentials in the URL (`user:pass@`) are `InvalidArgument`, because the HTTP client puts the URL in its error text and logs; pass the secret in `node_api_secret`. |
| `node_api_secret` | string or null | no | Node foreign API secret. Empty string is the same as null. |
| `socks_proxy` | string or null | no | `"host:port"` with an IPv4 literal host, optionally prefixed `socks5h://` or `socks5://`. Host names are rejected (resolving them would leak a DNS query) and so is IPv6. Traffic uses `socks5h`, so `.onion` names resolve inside Tor. |
| `request_timeout_secs` | u64 or null | no | Default 30. Must be greater than 0. |

Unknown keys are ignored. A missing required key or a wrong type is `Json`;
a bad value is `InvalidArgument`.

## 4. Memory, logging and diagnostics

### `grin_ffi_result_free(res)`, `grin_string_free(ptr)`

See 1.1.

### `grin_init_logs(log_level)`

- `log_level`: nullable string, one of `trace`, `debug`, `info`, `warn`,
  `error`, `off` (case-insensitive). NULL or empty means `info`.
- Returns nothing.
- The first call installs a stderr logger and a panic hook that logs panics
  through it. Later calls only change the level. If the host process already
  installed a Rust `log` logger, that logger keeps receiving the records.
- Errors: `InvalidArgument` for an unknown level.

## 5. Stateless utilities

### `grin_mnemonic_generate(word_count)`

- `word_count`: 12, 15, 18, 21 or 24. Entropy comes from the OS random source.
- Returns `{"mnemonic": "word1 word2 ..."}`.
- Errors: `InvalidArgument` for any other count.

### `grin_mnemonic_validate(mnemonic)`

- Returns `{"valid": bool, "word_count": u32}`. `word_count` is the number of
  whitespace-separated words, whether or not the mnemonic is valid.
- A bad mnemonic is not an error. Only a NULL pointer (`InvalidArgument`) or
  bad UTF-8 (`InvalidUtf8`) fail.

### `grin_address_validate(address, network)`

- Accepts, after trimming whitespace:
  - a slatepack address, `grin1...` for Mainnet and `tgrin1...` for every
    other network (upper case is accepted);
  - a v3 onion address: the 56-character label, with or without `.onion`,
    `http://` or `https://`, a trailing `/` or a trailing `/v2/foreign`;
  - an `http://` or `https://` URL without query, fragment or credentials.
- Returns:

```json
{
  "kind": "slatepack",
  "slatepack_address": "grin1...",
  "onion_v3_url": "http://<56 chars>.onion",
  "url": "http://<56 chars>.onion"
}
```

| Field | slatepack | onion | http |
|---|---|---|---|
| `kind` | `"slatepack"` | `"onion"` | `"http"` |
| `slatepack_address` | normalized lower case | derived from the onion key, with the HRP of `network` | null |
| `onion_v3_url` | `http://<label>.onion` | `http://<label>.onion` | null |
| `url` | same as `onion_v3_url` | scheme as given (default `http`) + `://<label>.onion` | `scheme://host[:port][/path]` |

  `url` is the base that a synchronous send posts to; it never ends in `/`
  or `/v2/foreign`.
- Errors: `InvalidArgument` (bad `network`), `InvalidAddress` (anything
  else, including a `grin1` address checked with a non-Mainnet `network` or a
  `tgrin1` address checked with Mainnet).

### `grin_node_test_connection(node_url, api_secret, socks_proxy)`

- `node_url` required; `api_secret` and `socks_proxy` nullable, same rules as
  section 3. Timeout is 30 seconds. No network parameter is needed: neither
  node call reads the chain type.
- Calls the node's `get_version` and `get_tip`.
- Returns
  `{"node_version": string, "block_header_version": u16, "height": u64, "hash": string}`.
- Errors: `InvalidArgument`, `Node`.

## 6. Wallet lifecycle

### `grin_wallet_create(config_json, mnemonic, password)`

- `mnemonic`: nullable. NULL creates a new 24-word seed; otherwise a 12 to 24
  word BIP39 mnemonic to restore. A restored wallet needs a
  `grin_wallet_scan` to find its outputs.
- `password`: required, may be empty.
- Creates `<wallet_dir>/wallet_data` (and parents), the encrypted
  `wallet.seed` and the database, then opens the wallet.
- Returns `{"handle": u64}`.
- If creation fails after this call made `wallet_data`, the directory is
  removed again. Nothing is written for a config or mnemonic error.
- A `wallet_data` without `wallet.seed` that still holds a database (`db/`
  or any `*.mdb` file, for example after a delete that stopped half way) is
  `WalletExists` with `"reason": "leftover_wallet_data"`: a new seed must not
  start on another seed's outputs, history and transaction contexts. Nothing
  is removed; `grin_wallet_delete` clears the directory.
- Errors: `Json`, `InvalidArgument`, `InvalidUtf8`, `InvalidMnemonic`,
  `WalletExists`, `WalletBusy`, `Lifecycle`, `Io`, `Node` (HTTP client could not
  be built).

### `grin_wallet_open(config_json, password)`

- Returns `{"handle": u64}`.
- Errors: `Json`, `InvalidArgument`, `InvalidUtf8`, `WalletNotFound`,
  `InvalidPassword`, `WalletBusy`, `Lifecycle`, `Io`.
- `InvalidPassword` means the seed file was read, is well formed and does
  not decrypt with `password`. A damaged `wallet.seed` is `Lifecycle`, an
  unreadable one `Io`.
- Neither create nor open contacts the node.

### `grin_wallet_close(handle)`

- Returns nothing. Removes the handle at once; the database closes and the
  directory is released when the last in-flight call on the wallet returns.
- Call it once per handle. A second call, or a call with an unknown handle,
  is `InvalidHandle`.

### `grin_wallet_close_finalizer(token)`

- `void (*)(void *)` for Dart's `NativeFinalizer`. `token` is the handle cast
  to a pointer (`Pointer.fromAddress(handle)`). Unknown handles are ignored.

### `grin_wallet_delete(wallet_dir, handle)`

- Deletes `<wallet_dir>/wallet_data` and everything in it. `wallet_dir`
  itself stays.
- `handle`: 0, or the handle of the wallet in this directory, which is closed
  first. The handle matches if it was opened at the same canonical path or
  at another path to the same directory (see the directory guard below). A
  handle that belongs to another directory is `InvalidArgument`; a handle
  that is not registered is ignored.
- A missing `wallet_data` counts as already deleted (success). If `handle`
  is registered and its own data directory is gone as well (removed outside
  the library), the handle is closed; if its data directory still exists, it
  belongs to another directory and the call is `InvalidArgument`.
- Returns nothing.
- Errors: `InvalidArgument`, `InvalidUtf8`, `WalletBusy` (another open wallet
  or a call still running on a closed one holds the directory; nothing is
  deleted), `Io`.

### Directory guard (`WalletBusy`)

A wallet directory can be held by at most one wallet in the process. It is
held from a successful create/open until the wallet is closed and every call
that was running on it has returned. While held, create, open and delete on
the same directory return `WalletBusy`. The guard is keyed by the identity
of the `wallet_data` directory, taken after create makes it and after open
and delete canonicalize it (a directory that does not exist has no
identity). On unix the identity is the device and inode number, so `dir`,
`dir/`, `dir/./`, symlinks to `dir`, a bind mount of it and a path to it
after a rename while it is open are all the same directory, and a directory
removed and made again at the same path is a different one. On Windows it is
the canonical path, which covers `dir`, `dir/`, `dir/./` and symlinks but not
other mounts of the same directory. The `wallet_dir` detail of `WalletBusy`
is the canonical path of the call that was refused. `wallet_data` itself must
not be a symlink to a directory with another name (`InvalidArgument`).

### `grin_wallet_change_password(handle, old_pw, new_pw)`

- Re-encrypts `wallet.seed`. Returns nothing.
- `old_pw` is checked first by decrypting the seed. Only that check gives
  `InvalidPassword` (or `WalletNotFound` if `wallet.seed` is missing,
  `Lifecycle` if it is damaged, `Io` if it cannot be read).
- Any failure after that is `Lifecycle` with the lifecycle provider's own
  message. The provider moves `wallet.seed` to `wallet.seed.bak` (or
  `.bak.N`) before writing the new file, so the message says where the seed
  encrypted with `old_pw` is, and `details` carries
  `{"seed_present": bool, "backup_file": string or null}`. With
  `seed_present: false`, renaming `backup_file` back to `wallet.seed`
  restores the wallet with the old password.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`,
  `InvalidPassword`, `WalletNotFound`, `Lifecycle`, `Io`.

### `grin_wallet_get_mnemonic(handle, password)`

- Returns `{"mnemonic": "word1 word2 ..."}`.
- `InvalidPassword` only when the seed file is present, well formed and
  does not decrypt; a missing file is `WalletNotFound`, a damaged one
  `Lifecycle`, an unreadable one `Io`.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`,
  `InvalidPassword`, `WalletNotFound`, `Lifecycle`, `Io`.

### `grin_wallet_update_network(handle, node_url, api_secret, socks_proxy)`

- `node_url` required; `api_secret` and `socks_proxy` nullable (section 3
  rules). Keeps the wallet's request timeout. Does not reopen the database
  and does not contact the node.
- The node client and the stored node settings (used for the proxy of
  `grin_tx_send_http`) change together while the wallet lock is held, so
  no call that holds the wallet lock sees one without the other.
- Returns nothing.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`, `Node`.

## 7. Address and chain

### `grin_wallet_get_address(handle, derivation_index)`

- Returns
  `{"slatepack_address": "grin1...", "onion_v3_url": "http://<56 chars>.onion", "index": u32}`.
  The prefix is `grin1` for Mainnet wallets and `tgrin1` for all others.
- Errors: `InvalidHandle`, `Lifecycle`.

### `grin_wallet_get_chain_height(handle)`

- Asks the wallet's node (through its proxy, if any) for the tip.
- Returns `{"height": u64, "hash": string}`.
- Errors: `InvalidHandle`, `Node`.

## 8. Sync, scan and balances

### `grin_wallet_get_balance(handle, refresh_from_node, min_confirms)`

- `refresh_from_node`: update outputs and transactions from the node first.
  If the node cannot be reached the stored state is returned with
  `refreshed_from_node: false`.
- Returns:

```json
{
  "last_confirmed_height": 1234567,
  "minimum_confirmations": 10,
  "total": 0,
  "amount_awaiting_finalization": 0,
  "amount_awaiting_confirmation": 0,
  "amount_immature": 0,
  "amount_currently_spendable": 0,
  "amount_locked": 0,
  "amount_reverted": 0,
  "refreshed_from_node": true
}
```

  All amounts are nanogrin `u64`, taken from libwallet's `WalletInfo`.
- Errors: `InvalidHandle`, `Lifecycle`, `Node`.

### `grin_wallet_scan(handle, start_height, delete_unconfirmed)`

- Scans the UTXO set from `start_height` (0 means from height 1) to the
  current tip and repairs the wallet's outputs. Transaction history is kept.
  Runs on the calling thread until done or cancelled.
- Steps, the same as libwallet's `owner::scan`: refresh every wallet output
  from the node (this also stores the node height as the wallet's
  `last_confirmed_height`; a refresh failure is only logged), read the tip,
  then scan in batches of 10,001 heights, saving the last scanned block
  after each batch (with the tip hash on the last one).
- Returns `{"scanned_height": u64, "tip_height": u64}`; on success both are
  the tip.
- Errors: `InvalidHandle`, `Node`, `Cancelled`, `WalletBusy` (a scan is
  already running on this wallet), `Lifecycle`, `Io`.
- Cancellation: before each batch the scan checks whether
  `grin_wallet_scan_cancel` was called or the handle was closed. If so it
  stops and returns `Cancelled` with
  `{"scanned_height": u64, "tip_height": u64}`, where `scanned_height` is
  the last height of the last batch that was saved (one below the
  effective start height when none was). Every batch up to there is saved,
  so a later scan can start from `scanned_height + 1`. A batch that has
  started always finishes, so a cancel can wait for up to one batch (10,001
  blocks and its node requests). A cancel that arrives after the last batch
  has nothing to stop and the scan succeeds.
- A cancel only reaches a scan that is running. Every scan starts with the
  cancel request cleared, so a cancel from earlier never stops a later
  scan. Closing the handle stops the running scan the same way, and a call
  that still holds a closed wallet cannot start a new scan (`Cancelled`
  without details). The database closes and the directory is released when
  the stopped scan returns.

### `grin_wallet_scan_progress(handle)`

- Takes no wallet lock, so it answers while a scan holds the wallet.
- Returns:

```json
{
  "is_scanning": false,
  "cancel_requested": false,
  "start_height": 1,
  "scanned_height": 5,
  "tip_height": 5,
  "progress_pct": 100
}
```

  The heights describe the current or most recent scan (all 0 before the
  first). They are reset when a scan starts: `start_height` to the
  effective start, `tip_height` and `scanned_height` to 0 until the tip is
  known, so a new scan never shows the previous one's 100%. While a batch
  runs, `scanned_height` is estimated from libwallet's percentage messages;
  after each batch it is at least that batch's last height. When the scan
  ends it is exact: `tip_height` on success, the last saved height on
  `Cancelled` or an error. `cancel_requested` is true from a cancel or close
  until the scan returns, and false once no scan is running.
  `progress_pct` is 0 to 100.
- Errors: `InvalidHandle`.

### `grin_wallet_scan_cancel(handle)`

- Takes no wallet lock and returns at once. Asks the running scan to stop
  before its next batch; the `grin_wallet_scan` call then returns
  `Cancelled` (see there). With no scan running it does nothing and returns
  success; it does not affect a scan started later.
- Returns nothing.
- Errors: `InvalidHandle`.
- The doc comment of this function in `include/grin_ffi.h` still describes
  the earlier behaviour (cancel before start); this section is the
  contract until the header is regenerated.

## 9. Transactions and Slatepacks

### 9.1 Common rules

- `slate_id` is the slate UUID as a lower-case hyphenated string. `tx_id`
  is the wallet's local log id (a `u32`, the `id` field of `grin_txs_get`).
- Functions that take `tx_id: i64` and `slate_id` (repost, cancel, proof
  export) treat a negative `tx_id` as absent and a NULL or empty `slate_id`
  as absent. At least one must be given, otherwise `InvalidArgument`; so is
  a `tx_id` above `u32::MAX` or a `slate_id` that is not a UUID. When both
  are given, cancel and proof export need both to match the same
  transaction; repost looks up `tx_id` first and falls back to `slate_id`.
- Slatepack addresses in arguments and results are `grin1...` for Mainnet
  wallets and `tgrin1...` for all others. An address for the other network
  is `InvalidAddress`.
- Encrypted Slatepacks are decrypted with the wallet's address key at
  index 0 (`grin_slatepack_decode` takes the index as an argument). A
  Slatepack this wallet produces always names the wallet's index 0 address
  as its sender.
- After the wallet has recorded a transaction (outputs locked, slate
  received or finalized), a later failure adds `{"slate_id": string}` to the
  error's `details`, so the caller can still cancel or repost it. This
  applies to any code, including `Node` when a broadcast fails. Finalizing
  (`grin_tx_finalize_slatepack`, `grin_tx_finalize_invoice`) acts on a
  transaction this wallet recorded when it made the S1 or I1, so every
  failure after the Slatepack is decoded and its state checked carries it;
  `grin_tx_process_invoice` adds it to failures after
  `process_invoice_tx` saved the transaction (locking the inputs and
  later).
- Arguments JSON: unknown keys are ignored. A missing required key or a
  wrong type is `Json`; a bad value is `InvalidArgument`. Optional keys may
  be absent or `null`.
- Every transaction function may also fail with `InvalidHandle`, `Node`
  (the node could not be reached), `Lifecycle` and `Internal`.
- The sidecar file (`tx_metadata.json`, docs/architecture.md 4.4) is
  written after each step that produces a Slatepack. Its writes are best
  effort: a failure is logged and never fails the call. Only a missing file
  starts empty; a file that cannot be read, does not parse or has a newer
  format version is left untouched and the write is skipped (and logged),
  so stored Slatepacks and addresses are never replaced by one entry.

### 9.2 `GrinSlatepack` result

Returned by `grin_tx_init_send` (S1), `grin_tx_receive_slatepack` (S2),
`grin_tx_issue_invoice` (I1) and `grin_tx_process_invoice` (I2):

```json
{
  "slate_id": "2b1c...",
  "state": "S1",
  "armored_slatepack": "BEGINSLATEPACK. ... . ENDSLATEPACK.\n",
  "amount": 50000000000,
  "fee": 23500000,
  "sender": "tgrin1...",
  "recipients": ["tgrin1..."],
  "is_encrypted": true
}
```

| Field | Type | Meaning |
|---|---|---|
| `slate_id` | string | Slate UUID. |
| `state` | string | `S1`, `S2`, `I1` or `I2`. |
| `armored_slatepack` | string | The Slatepack to hand to the other party. |
| `amount` | u64 | Amount the transaction moves. Slates on the return journey carry 0, so S2 and I2 report the amount of the incoming S1 or I1. |
| `fee` | u64 | Fee. 0 on I1 (the payer sets the fee); S2 reports the fee of the incoming S1. |
| `sender` | string | This wallet's index 0 address, embedded in the Slatepack. |
| `recipients` | array of string | Addresses the Slatepack is encrypted to; empty when it is not encrypted. |
| `is_encrypted` | bool | `recipients` is not empty. |

### 9.3 `GrinFinalized` result

Returned by `grin_tx_finalize_slatepack` (S3) and `grin_tx_finalize_invoice`
(I3):

```json
{
  "slate_id": "2b1c...",
  "state": "S3",
  "amount": 50000000000,
  "fee": 23500000,
  "kernel_excess": "08a1...",
  "posted": true,
  "armored_slatepack": "BEGINSLATEPACK. ... . ENDSLATEPACK.\n"
}
```

| Field | Type | Meaning |
|---|---|---|
| `amount` | u64 | From this wallet's log entry: the amount sent (without the fee) or received. |
| `fee` | u64 | Fee of the final transaction. |
| `kernel_excess` | string | Hex (66 characters) of the final kernel excess, the key a payment proof and a block explorer use. |
| `posted` | bool | `broadcast` as given; true means the node accepted the transaction. |
| `armored_slatepack` | string | The finalized slate as an unencrypted Slatepack without sender, for reference. It is also stored in the sidecar. |

If the broadcast fails, the call fails with `Node` and `details`
`{"slate_id"}`. The transaction is finalized and stored by then; broadcast
it with `grin_tx_repost`.

### `grin_tx_estimate_fee(handle, amount, min_confirms, selection_strategy_is_all, amount_includes_fee)`

- `amount`: nanogrin, greater than 0. With `amount_includes_fee` the fee is
  taken out of `amount`, otherwise it is added on top.
- `min_confirms`: confirmations an output needs to be spent.
- `selection_strategy_is_all`: true spends all spendable outputs (up to
  500), false only as many of the smallest as needed.
- Refreshes outputs from the node, selects inputs and computes the fee
  exactly as a send would, but saves and locks nothing.
- Returns:

```json
{"fee": 23500000, "amount": 50000000000, "net_amount": 50000000000, "total": 50023500000, "inputs_count": 1, "change_outputs": 1}
```

| Field | Meaning |
|---|---|
| `fee` | Fee in nanogrin. |
| `amount` | Net amount the recipient gets. |
| `net_amount` | Same as `amount` (the name the header comment uses). |
| `total` | `amount + fee`, what leaves the wallet apart from change. |
| `inputs_count` | Outputs the send would spend. |
| `change_outputs` | 0 when the inputs add up exactly, otherwise 1. |

- libwallet can price a change output into the fee and then find that the
  change comes out at exactly 0 (no change output is made, but the fee
  keeps the output's weight). `inputs_count` accounts for that: when the
  fee alone fits both ways, a second estimate under the same wallet lock
  tells them apart.

- Errors: `InvalidArgument` (`amount` 0), `InsufficientFunds` with
  `{"required": u64, "available": u64}`, `Transaction` (with
  `amount_includes_fee`, an amount smaller than the fee).

### `grin_txs_get(handle, refresh_from_node)`

- `refresh_from_node`: update outputs and transaction states from the node
  first. If the node cannot be reached the stored history is returned with
  `refreshed_from_node: false`.
- Returns `{"refreshed_from_node": bool, "txs": [entry, ...]}` in log order.
  Each entry:

| Field | Type | Meaning |
|---|---|---|
| `id` | u32 | Local log id (the `tx_id` of other functions). |
| `slate_id` | string or null | Slate UUID; null for coinbase. |
| `slate_state` | string or null | Last slate state this wallet saw: `S1` `S2` `S3` `I1` `I2` `I3`, or `Unknown`. |
| `type` | string | `ConfirmedCoinbase`, `TxReceived`, `TxSent`, `TxReceivedCancelled`, `TxSentCancelled` or `TxReverted`. |
| `creation_ts` | string | RFC 3339 UTC timestamp. |
| `confirmation_ts` | string or null | RFC 3339, when this wallet saw it confirmed. |
| `confirmed` | bool | |
| `num_inputs`, `num_outputs` | integer | This wallet's inputs and outputs in the transaction. |
| `amount_credited`, `amount_debited` | u64 | What came in (including change) and went out. |
| `fee` | u64 or null | |
| `ttl_cutoff_height` | u64 or null | |
| `kernel_excess` | string or null | Hex of the kernel excess libwallet recorded for kernel lookups. |
| `kernel_lookup_min_height` | u64 or null | |
| `has_stored_tx` | bool | A finalized transaction (state S3 or I3) is stored, so `grin_tx_repost` can broadcast it. libwallet also keeps an unsigned copy from the moment outputs are locked; that does not count. |
| `payment_proof` | object or null | `{"receiver_address", "sender_address", "receiver_signature_present", "sender_signature_present"}`, addresses as slatepack strings. Only the sender of a transaction that asked for a proof has one. |
| `counterparty_address` | string or null | For sends with a proof, the receiver; for receipts with a proof, the sender; otherwise the address or URL from the sidecar. |
| `armored_slatepack` | string or null | Latest Slatepack from the sidecar (S1, S2, I1, I2, or the S3/I3 written at finalization). |
| `reverted_after_secs` | u64 or null | |

- Errors: `InvalidHandle`, `Lifecycle`.

### `grin_slatepack_decode(handle, network, armored_slatepack, secret_index)`

- `handle` 0: no wallet. The thread's chain type comes from `network` and
  only unencrypted Slatepacks can be read; an encrypted one is `Slate` with
  message `"encrypted slatepack needs an open wallet"`.
- `handle` non-zero: the wallet's network is used (`network` is ignored)
  and an encrypted Slatepack is decrypted with the wallet's address key at
  `secret_index`. If that key does not fit, `Slate`.
- Leading and trailing whitespace is ignored. Besides armor, raw binary or
  JSON slatepack data is accepted.
- Returns:

```json
{
  "slate_id": "2b1c...",
  "state": "S1",
  "amount": 50000000000,
  "fee": 23500000,
  "kernel_excess": null,
  "sender": "tgrin1...",
  "recipients": [],
  "ttl_cutoff_height": null,
  "num_participants": 2,
  "is_encrypted": true,
  "slate_json": "{\"id\":\"2b1c...\", ...}"
}
```

| Field | Type | Meaning |
|---|---|---|
| `state` | string | `S1` `S2` `S3` `I1` `I2` `I3`, or `Unknown` for a pre-V4 slate. |
| `amount` | u64 | As carried by the slate: 0 on S2, S3, I2 and I3, which libwallet clears on the return journey. |
| `fee` | u64 | The slate's fee fields, or the kernel fee when those were cleared. 0 on S2 and I1. |
| `kernel_excess` | string or null | Hex of the final kernel excess; only S3 and I3 have one. |
| `sender` | string or null | Sender address in the Slatepack (inside the encryption when encrypted). |
| `recipients` | array of string | Recipient list from the encrypted metadata. libwallet does not write one, so this is normally empty; `is_encrypted` tells whether the payload was encrypted. |
| `ttl_cutoff_height` | u64 or null | |
| `num_participants` | integer | |
| `is_encrypted` | bool | The payload was age-encrypted. |
| `slate_json` | string | The slate as V4 JSON text (what the foreign API exchanges). |

- Errors: `InvalidArgument` (bad `network` with handle 0), `InvalidHandle`,
  `InvalidUtf8`, `Slate`.

### `grin_tx_init_send(handle, args_json)`

```json
{
  "amount": 50000000000,
  "min_confirms": 10,
  "selection_strategy_is_all": false,
  "amount_includes_fee": false,
  "recipient_address": "tgrin1...",
  "ttl_blocks": null,
  "message": null,
  "late_lock": false
}
```

| Key | Type | Default | Notes |
|---|---|---|---|
| `amount` | u64 | required | Greater than 0 and at most 2^63 - 1 (an overflow guard; libwallet adds the fee to it unchecked). |
| `min_confirms` | u64 | 10 | |
| `selection_strategy_is_all` | bool | false | See `grin_tx_estimate_fee`. |
| `amount_includes_fee` | bool | false | |
| `recipient_address` | string or null | null | Recipient's slatepack address. When given, the S1 is encrypted to it and a payment proof is requested from it. |
| `ttl_blocks` | u64 or null | null | Blocks until the transaction expires; 1 to 1,000,000,000. |
| `message` | any | | Accepted and ignored: Slate V4 has no message. |
| `late_lock` | bool | false | When true, inputs are selected and locked at finalization instead of now. |

- Builds the S1, locks its inputs (unless `late_lock`), and returns a
  `GrinSlatepack` (9.2) with state `S1`. The sidecar gets the Slatepack and
  `recipient_address`.
- Cancel an S1 that will not be completed with `grin_tx_cancel`.
- Errors: `InvalidArgument`, `Json`, `InvalidAddress`, `InsufficientFunds`,
  `Transaction`, `Slate`.

### `grin_tx_send_http(handle, args_json)`

- `args_json`: every key of `grin_tx_init_send` plus:

| Key | Type | Default | Notes |
|---|---|---|---|
| `recipient_url_or_address` | string | required | A slatepack address, a v3 onion address or an `http(s)://` URL, in any form `grin_address_validate` accepts. |
| `fluff` | bool | false | Broadcast without Dandelion stem phase. |
| `post` | bool | true | Broadcast after finalizing. |

- Target: a slatepack address becomes its `http://<onion>.onion` URL, an
  onion address its onion URL, and an `http(s)` URL is used as given.
  `/v2/foreign` is appended. Anything that resolves to `.onion` needs a
  SOCKS proxy in the wallet's network settings, otherwise
  `InvalidArgument`. When the wallet has a proxy, every send goes through
  it, clearnet URLs included.
- Payment proof: requested from the slatepack address when the target is
  one. For an onion or URL target, `recipient_address` requests one. A
  slatepack or onion target is itself a slatepack key, so a
  `recipient_address` for another key is `InvalidArgument`, checked before
  anything is built or locked (and before the proxy check).
- Order: build the S1 (nothing locked yet), `check_version` and
  `receive_tx` on the other wallet with the wallet mutex released, lock the
  inputs, finalize, broadcast when `post`. A failed exchange leaves nothing
  locked and nothing in the history.
- Returns
  `{"slate_id", "state": "S3", "amount": u64, "fee": u64, "kernel_excess": string, "posted": bool}`.
  The sidecar records the target as `counterparty_address`; there is no
  Slatepack.
- Errors: `InvalidArgument`, `Json`, `InvalidAddress`, `InsufficientFunds`,
  `Http` (the other wallet could not be reached, refused the slate or
  answered with something else), `Transaction`, `Node` with `{"slate_id"}`
  (finalized but not broadcast).

### `grin_tx_receive_slatepack(handle, armored_s1, message)`

- `armored_s1`: an S1 Slatepack, plain or encrypted to this wallet.
- `message`: nullable, ignored (Slate V4 has no message).
- Adds this wallet's output and signature and returns a `GrinSlatepack`
  with state `S2`. When the S1 named a sender, the S2 is encrypted to it.
  The sidecar gets the S2 and the sender's address.
- Errors: `Slate` (not a Slatepack, cannot be decrypted, or not an S1; the
  message names the expected state), `Transaction` (already received,
  expired), `InvalidUtf8`.

### `grin_tx_finalize_slatepack(handle, armored_s2, broadcast, fluff)`

- `armored_s2`: the S2 for a transaction this wallet started.
- Finalizes and, when `broadcast`, posts the transaction. Returns a
  `GrinFinalized` (9.3) with state `S3`.
- Errors: `Slate` (not an S2), `NotFound` (this wallet has no open
  transaction for the slate: unknown, or already finalized), `Transaction`
  (bad signature, payment proof mismatch, expired), `Node`. Every failure
  after the S2 is decoded carries `{"slate_id"}`.

## 10. Invoices, repost, cancel and proofs

### `grin_tx_issue_invoice(handle, args_json)`

```json
{"amount": 30000000000, "dest_acct_name": null, "recipient_address": "tgrin1..."}
```

| Key | Type | Default | Notes |
|---|---|---|---|
| `amount` | u64 | required | Greater than 0 and at most 2^63 - 1. |
| `dest_acct_name` | string or null | null | Wallet account to receive into; unknown names fall back to the default account. |
| `recipient_address` | string or null | null | The payer's slatepack address. When given, the I1 is encrypted to it. |

- Returns a `GrinSlatepack` with state `I1` (`fee` 0). The receipt shows in
  `grin_txs_get` as `TxReceived` at once.
- Errors: `InvalidArgument`, `Json`, `InvalidAddress`, `Transaction`.

### `grin_tx_process_invoice(handle, armored_i1, args_json)`

```json
{"min_confirms": 10, "selection_strategy_is_all": false, "ttl_blocks": null}
```

| Key | Type | Default |
|---|---|---|
| `min_confirms` | u64 | 10 |
| `selection_strategy_is_all` | bool | false |
| `ttl_blocks` | u64 or null | null (1 to 1,000,000,000 when given) |

- Pays the invoice: selects inputs, signs, and locks the inputs in the same
  call (libwallet's `process_invoice_tx` does not lock them by itself).
  Returns a `GrinSlatepack` with state `I2`, encrypted to the invoicer when
  the I1 named one.
- An I1 whose amount is above 2^63 - 1 is `InvalidArgument`, before
  anything is selected or locked.
- Errors: `Slate` (not an I1), `InsufficientFunds`, `Transaction`
  (already paid or cancelled, expired), `Json`, `InvalidArgument`. A
  failure after libwallet saved the payment (locking the inputs, armoring
  the I2) carries `{"slate_id"}`.

### `grin_tx_finalize_invoice(handle, armored_i2, broadcast, fluff)`

- `armored_i2`: the I2 for an invoice this wallet issued.
- Returns a `GrinFinalized` with state `I3`.
- Errors: as `grin_tx_finalize_slatepack`, with `Slate` for anything that
  is not an I2.

### `grin_tx_repost(handle, tx_id, slate_id, fluff)`

- Broadcasts the stored finalized transaction again (9.1 for the
  identifiers). The transaction is validated first.
- A cancelled entry (`TxSentCancelled`, `TxReceivedCancelled`) is refused
  with `Transaction`, even when a finalized copy is stored.
- Returns `{"posted": true}`.
- Errors: `InvalidArgument`, `NotFound` (no such transaction, nothing
  stored, or the stored copy is not finalized yet), `Transaction`
  (cancelled), `Node` with `{"slate_id"}`.

### `grin_tx_cancel(handle, tx_id, slate_id)`

- Cancels an unconfirmed `TxSent`, `TxReceived` or `TxReverted` entry:
  locked inputs become spendable again and its new outputs are dropped. The
  entry becomes `TxSentCancelled` or `TxReceivedCancelled`. libwallet first
  refreshes from the node and refuses to cancel without it.
- Returns `{"cancelled": true}`.
- Errors: `InvalidArgument`, `NotFound`, `Transaction` (confirmed, a
  coinbase, or already cancelled), `Node`.

### `grin_payment_proof_export(handle, tx_id, slate_id)`

- Only the sender of a finalized transaction that asked for a proof has
  one. Uses the stored history (no node refresh).
- Returns `{"proof": PaymentProof}` where `PaymentProof` is libwallet's own
  serde format, which `grin_payment_proof_verify` reads back:

```json
{
  "proof": {
    "amount": "50000000000",
    "excess": "08a1...",
    "recipient_address": "tgrin1...",
    "recipient_sig": "<128 hex characters>",
    "sender_address": "tgrin1...",
    "sender_sig": "<128 hex characters>"
  }
}
```

  Note `amount` is a decimal string in this format, unlike every other
  amount in this document.
- Errors: `InvalidArgument`, `NotFound` (no such transaction, no proof, or
  the proof is not complete yet because the transaction is not finalized).

### `grin_payment_proof_verify(handle, proof_json)`

- `proof_json`: the export result `{"proof": {...}}` or the bare proof
  object. Its addresses must be for the wallet's network.
- Checks that the kernel is on chain (through the wallet's node) and both
  signatures, then compares the addresses with this wallet's index 0
  address.
- Returns `{"is_sender": bool, "is_recipient": bool}`. Both false means the
  proof is valid but belongs to two other wallets.
- Errors: `Json` (not a proof object, or an address for another network),
  `Transaction` (a signature does not verify or the kernel is not on
  chain), `Node`.

## 11. Test-only functions (`test-utils` feature)

Declared in the header only under `#ifdef GRIN_FFI_TEST_UTILS` and exported
only by builds with `--features test-utils`. Release artifacts export none.

### `grin_test_create_wallet(chain_dir, wallet_dir, client_id, network, mnemonic, password)`

- Starts (on first use per `chain_dir`) an in-process chain at
  AutomatedTesting (coinbase maturity 3) with a wallet proxy thread, then
  creates the wallet in `<wallet_dir>/wallet_data`, or opens it if
  `wallet.seed` exists (the mnemonic is then ignored), connected to that chain
  as `client_id`.
- `client_id`: non-empty, unique per chain, not `"node"`. Reusing an id
  re-attaches that wallet. `mnemonic` nullable as in `grin_wallet_create`.
- Takes the same directory guard as `grin_wallet_open`. The handle works with
  every handle function.
- Every `network` is accepted so tests can check keychains and address
  prefixes, but the chain is always AutomatedTesting; funded flows should use
  `network` 3.
- Returns `{"handle": u64}`.

### `grin_test_mine_blocks(handle, count)`

- Mines `count` blocks whose coinbase pays the wallet behind `handle`.
- Returns `{"height": u64}` (chain height afterwards).
- Errors: `InvalidHandle`, `InvalidArgument` (not a test wallet).

### `grin_test_panic()`

- Always fails with `InternalPanic` and message `"grin_test_panic"`.
