# grin-ffi JSON contract

This is the data contract between `crates/grin-ffi` and the Dart package
`packages/grin`. The C signatures are in `crates/grin-ffi/include/grin_ffi.h`
(generated by cbindgen, committed) and in docs/architecture.md section 4.6.
This document covers what goes inside the strings.

## 1. Conventions

### 1.1 Result struct

Every function except the three `void` ones returns:

```c
typedef struct GrinFfiResult {
  int32_t code;   /* 0 on success, otherwise a GrinErrorCode */
  char   *data;   /* success: JSON text, or NULL when there is nothing to return */
  char   *error;  /* failure: error JSON (section 2), otherwise NULL */
} GrinFfiResult;
```

- On success `code == 0`, `error == NULL`, and `data` is either a JSON document
  or NULL. Functions documented as returning "nothing" always give NULL.
- On failure `code != 0`, `data == NULL`, and `error` is the error JSON.
- Free every result exactly once with `grin_ffi_result_free(res)`. It zeroes
  both strings before freeing them (results can hold a mnemonic).
  `grin_string_free(ptr)` frees a single string from this library. Both accept
  NULL members.
- The `void` functions are `grin_ffi_result_free`, `grin_string_free` and
  `grin_wallet_close_finalizer`. They never fail and never unwind.

### 1.2 Arguments

- `const char *` arguments are NUL-terminated UTF-8. Invalid UTF-8 gives
  `InvalidUtf8` (2).
- A NULL pointer gives `InvalidArgument` (1) unless the argument is listed as
  nullable below.
- For nullable `api_secret` and `socks_proxy` arguments, an empty string is
  treated the same as NULL.
- Passwords and mnemonics are copied into zeroing buffers on entry and never
  logged. The caller still owns (and should zero) its own copy.
- `network: u8` is `0` Mainnet, `1` Testnet (Floonet), `2` UserTesting,
  `3` AutomatedTesting. Anything else is `InvalidArgument`. This numbering is
  our own and does not follow the order of `ChainTypes` in grin_core.

### 1.3 Panics, threads and chain type

- Every body runs inside `catch_unwind`. A Rust panic becomes
  `InternalPanic` (16) with the panic message in `message`.
- Calls are synchronous and may be made from any thread. There is no
  process-wide chain type: each call sets the calling thread's chain type
  from its `network` argument, its config, or the wallet behind its handle.
  A Mainnet and a Testnet wallet can be used at the same time from the same
  threads.
- Handles are non-zero `u64` values, never reused within a process. `0` and
  unknown values give `InvalidHandle` (7).

### 1.4 Numbers

All amounts are `u64` nanogrin (1 grin = 1,000,000,000 nanogrin) written as
JSON integers. Heights are `u64` integers. Nothing is a float or a decimal
string.

## 2. Errors

### 2.1 Error JSON

```json
{"code": 18, "message": "the wallet directory is in use by an open or still closing wallet", "details": {"wallet_dir": "/data/w/wallet_data"}}
```

| Field | Type | Meaning |
|---|---|---|
| `code` | integer | Same value as `GrinFfiResult.code`. |
| `message` | string | Human-readable English text. Not stable; do not parse it. |
| `details` | object or null | Structured data for some codes, listed below. |

### 2.2 Codes

Values are append-only; Dart maps them by number.

| Code | Name | Meaning | `details` |
|---:|---|---|---|
| 0 | `Ok` | Success. Never appears in an error JSON. | |
| 1 | `InvalidArgument` | NULL where not allowed, out-of-range value, bad URL or proxy, handle for another directory. | null |
| 2 | `InvalidUtf8` | A string argument is not valid UTF-8. | null |
| 3 | `Json` | A JSON argument does not parse or misses a required key. | null |
| 4 | `WalletNotFound` | No `wallet_data` directory or no `wallet.seed` in it. | `{"wallet_dir": string}` (as given) |
| 5 | `InvalidPassword` | The password does not decrypt `wallet.seed`. | null |
| 6 | `WalletExists` | `grin_wallet_create` on a directory that already has `wallet.seed`. | `{"wallet_dir": string}` (as given) |
| 7 | `InvalidHandle` | Handle is 0, unknown, or already closed. | null |
| 8 | `Lifecycle` | Other wallet open/close/seed failures from the lifecycle provider. | null |
| 9 | `Node` | The node could not be reached or gave an unusable answer. | null |
| 10 | `InsufficientFunds` | Not enough spendable funds. | `{"required": u64, "available": u64}` |
| 11 | `Slate` | Slate or Slatepack could not be parsed, encrypted, decrypted or is in the wrong state. | null |
| 12 | `Transaction` | Transaction building or bookkeeping failed. | null |
| 13 | `NotFound` | Transaction or payment proof does not exist. | null |
| 14 | `Cancelled` | A scan was cancelled before it started. | null |
| 15 | `Io` | File system error. | null |
| 16 | `InternalPanic` | A Rust panic was caught. | null |
| 17 | `Internal` | Unexpected internal error. | null |
| 18 | `WalletBusy` | The wallet directory is held by an open wallet or one still closing, or a scan is already running. | `{"wallet_dir": string}` (canonical path); for a running scan also `"reason": "scan_in_progress"` |
| 19 | `Http` | Wallet-to-wallet HTTP communication failed. | null |
| 20 | `NotSupported` | The function is not implemented in this build. | null |
| 21 | `InvalidAddress` | Not a valid slatepack address, onion address or URL, or a slatepack address for the other network. | null |
| 22 | `InvalidMnemonic` | Mnemonic has a word outside the BIP39 English list, a bad checksum, or a bad length. The message never repeats the words. | null |

## 3. Wallet config (`config_json`)

Used by `grin_wallet_create` and `grin_wallet_open`.

```json
{
  "wallet_dir": "/data/user/0/app/files/grin/main",
  "network": 0,
  "node_url": "https://grinnode.example.com:3413",
  "node_api_secret": null,
  "socks_proxy": "127.0.0.1:9050",
  "request_timeout_secs": 30
}
```

| Key | Type | Required | Notes |
|---|---|---|---|
| `wallet_dir` | string | yes | Must not be empty. Wallet files live in `<wallet_dir>/wallet_data` (`wallet.seed`, `db/`, `saved_txs/`, `tx_metadata.json`). Nothing else in `wallet_dir` is touched. |
| `network` | u8 | yes | See 1.2. |
| `node_url` | string | yes | `http://` or `https://` base URL of a node's API. A trailing `/` is removed; `/v2/foreign` is appended internally. |
| `node_api_secret` | string or null | no | Node foreign API secret. Empty string is the same as null. |
| `socks_proxy` | string or null | no | `"host:port"` with an IPv4 literal host, optionally prefixed `socks5h://` or `socks5://`. Host names are rejected (resolving them would leak a DNS query) and so is IPv6. Traffic uses `socks5h`, so `.onion` names resolve inside Tor. |
| `request_timeout_secs` | u64 or null | no | Default 30. Must be greater than 0. |

Unknown keys are ignored. A missing required key or a wrong type is `Json`;
a bad value is `InvalidArgument`.

## 4. Memory, logging and diagnostics

### `grin_ffi_result_free(res)`, `grin_string_free(ptr)`

See 1.1.

### `grin_init_logs(log_level)`

- `log_level`: nullable string, one of `trace`, `debug`, `info`, `warn`,
  `error`, `off` (case-insensitive). NULL or empty means `info`.
- Returns nothing.
- The first call installs a stderr logger and a panic hook that logs panics
  through it. Later calls only change the level. If the host process already
  installed a Rust `log` logger, that logger keeps receiving the records.
- Errors: `InvalidArgument` for an unknown level.

## 5. Stateless utilities

### `grin_mnemonic_generate(word_count)`

- `word_count`: 12, 15, 18, 21 or 24. Entropy comes from the OS random source.
- Returns `{"mnemonic": "word1 word2 ..."}`.
- Errors: `InvalidArgument` for any other count.

### `grin_mnemonic_validate(mnemonic)`

- Returns `{"valid": bool, "word_count": u32}`. `word_count` is the number of
  whitespace-separated words, whether or not the mnemonic is valid.
- A bad mnemonic is not an error. Only a NULL pointer (`InvalidArgument`) or
  bad UTF-8 (`InvalidUtf8`) fail.

### `grin_address_validate(address, network)`

- Accepts, after trimming whitespace:
  - a slatepack address, `grin1...` for Mainnet and `tgrin1...` for every
    other network (upper case is accepted);
  - a v3 onion address: the 56-character label, with or without `.onion`,
    `http://` or `https://`, a trailing `/` or a trailing `/v2/foreign`;
  - an `http://` or `https://` URL without query, fragment or credentials.
- Returns:

```json
{
  "kind": "slatepack",
  "slatepack_address": "grin1...",
  "onion_v3_url": "http://<56 chars>.onion",
  "url": "http://<56 chars>.onion"
}
```

| Field | slatepack | onion | http |
|---|---|---|---|
| `kind` | `"slatepack"` | `"onion"` | `"http"` |
| `slatepack_address` | normalized lower case | derived from the onion key, with the HRP of `network` | null |
| `onion_v3_url` | `http://<label>.onion` | `http://<label>.onion` | null |
| `url` | same as `onion_v3_url` | scheme as given (default `http`) + `://<label>.onion` | `scheme://host[:port][/path]` |

  `url` is the base that a synchronous send posts to; it never ends in `/`
  or `/v2/foreign`.
- Errors: `InvalidArgument` (bad `network`), `InvalidAddress` (anything
  else, including a `grin1` address checked with a non-Mainnet `network` or a
  `tgrin1` address checked with Mainnet).

### `grin_node_test_connection(node_url, api_secret, socks_proxy)`

- `node_url` required; `api_secret` and `socks_proxy` nullable, same rules as
  section 3. Timeout is 30 seconds. No network parameter is needed: neither
  node call reads the chain type.
- Calls the node's `get_version` and `get_tip`.
- Returns
  `{"node_version": string, "block_header_version": u16, "height": u64, "hash": string}`.
- Errors: `InvalidArgument`, `Node`.

## 6. Wallet lifecycle

### `grin_wallet_create(config_json, mnemonic, password)`

- `mnemonic`: nullable. NULL creates a new 24-word seed; otherwise a 12 to 24
  word BIP39 mnemonic to restore. A restored wallet needs a
  `grin_wallet_scan` to find its outputs.
- `password`: required, may be empty.
- Creates `<wallet_dir>/wallet_data` (and parents), the encrypted
  `wallet.seed` and the database, then opens the wallet.
- Returns `{"handle": u64}`.
- If creation fails after this call made `wallet_data`, the directory is
  removed again. Nothing is written for a config or mnemonic error.
- Errors: `Json`, `InvalidArgument`, `InvalidUtf8`, `InvalidMnemonic`,
  `WalletExists`, `WalletBusy`, `Lifecycle`, `Io`, `Node` (HTTP client could not
  be built).

### `grin_wallet_open(config_json, password)`

- Returns `{"handle": u64}`.
- Errors: `Json`, `InvalidArgument`, `InvalidUtf8`, `WalletNotFound`,
  `InvalidPassword`, `WalletBusy`, `Lifecycle`, `Io`.
- Neither create nor open contacts the node.

### `grin_wallet_close(handle)`

- Returns nothing. Removes the handle at once; the database closes and the
  directory is released when the last in-flight call on the wallet returns.
- Call it once per handle. A second call, or a call with an unknown handle,
  is `InvalidHandle`.

### `grin_wallet_close_finalizer(token)`

- `void (*)(void *)` for Dart's `NativeFinalizer`. `token` is the handle cast
  to a pointer (`Pointer.fromAddress(handle)`). Unknown handles are ignored.

### `grin_wallet_delete(wallet_dir, handle)`

- Deletes `<wallet_dir>/wallet_data` and everything in it. `wallet_dir`
  itself stays.
- `handle`: 0, or the handle of the wallet in this directory, which is closed
  first. A handle that belongs to another directory is `InvalidArgument`; a
  handle that is not registered is ignored.
- A missing `wallet_data` counts as already deleted (success).
- Returns nothing.
- Errors: `InvalidArgument`, `InvalidUtf8`, `WalletBusy` (another open wallet
  or a call still running on a closed one holds the directory; nothing is
  deleted), `Io`.

### Directory guard (`WalletBusy`)

A wallet directory can be held by at most one wallet in the process. It is
held from a successful create/open until the wallet is closed and every call
that was running on it has returned. While held, create, open and delete on
the same directory return `WalletBusy`. Paths are compared after
canonicalization, so `dir`, `dir/`, `dir/./` and symlinks to `dir` are the
same directory. `wallet_data` itself must not be a symlink to a directory with
another name (`InvalidArgument`).

### `grin_wallet_change_password(handle, old_pw, new_pw)`

- Re-encrypts `wallet.seed`. Returns nothing.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`,
  `InvalidPassword`, `Lifecycle`, `Io`.

### `grin_wallet_get_mnemonic(handle, password)`

- Returns `{"mnemonic": "word1 word2 ..."}`.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`,
  `InvalidPassword`, `Lifecycle`.

### `grin_wallet_update_network(handle, node_url, api_secret, socks_proxy)`

- `node_url` required; `api_secret` and `socks_proxy` nullable (section 3
  rules). Keeps the wallet's request timeout. Does not reopen the database
  and does not contact the node.
- Returns nothing.
- Errors: `InvalidHandle`, `InvalidArgument`, `InvalidUtf8`, `Node`.

## 7. Address and chain

### `grin_wallet_get_address(handle, derivation_index)`

- Returns
  `{"slatepack_address": "grin1...", "onion_v3_url": "http://<56 chars>.onion", "index": u32}`.
  The prefix is `grin1` for Mainnet wallets and `tgrin1` for all others.
- Errors: `InvalidHandle`, `Lifecycle`.

### `grin_wallet_get_chain_height(handle)`

- Asks the wallet's node (through its proxy, if any) for the tip.
- Returns `{"height": u64, "hash": string}`.
- Errors: `InvalidHandle`, `Node`.

## 8. Sync, scan and balances

### `grin_wallet_get_balance(handle, refresh_from_node, min_confirms)`

- `refresh_from_node`: update outputs and transactions from the node first.
  If the node cannot be reached the stored state is returned with
  `refreshed_from_node: false`.
- Returns:

```json
{
  "last_confirmed_height": 1234567,
  "minimum_confirmations": 10,
  "total": 0,
  "amount_awaiting_finalization": 0,
  "amount_awaiting_confirmation": 0,
  "amount_immature": 0,
  "amount_currently_spendable": 0,
  "amount_locked": 0,
  "amount_reverted": 0,
  "refreshed_from_node": true
}
```

  All amounts are nanogrin `u64`, taken from libwallet's `WalletInfo`.
- Errors: `InvalidHandle`, `Lifecycle`, `Node`.

### `grin_wallet_scan(handle, start_height, delete_unconfirmed)`

- Scans the UTXO set from `start_height` (0 means from height 1) to the
  current tip and repairs the wallet's outputs. Transaction history is kept.
  Runs on the calling thread until done.
- Returns `{"scanned_height": u64, "tip_height": u64}`.
- Errors: `InvalidHandle`, `Node`, `Cancelled`, `WalletBusy` (a scan is
  already running on this wallet), `Lifecycle`, `Io`.
- Cancellation, current limitation: libwallet's scan has no hook between its
  10,000-block batches, so a scan that has started cannot be stopped.
  `grin_wallet_scan_cancel` sets a flag; if no scan is running, the next
  `grin_wallet_scan` returns `Cancelled` without starting and clears the flag.
  If a scan is running it finishes normally and the flag is cleared when it
  returns. Closing a wallet also sets the flag.

### `grin_wallet_scan_progress(handle)`

- Takes no wallet lock, so it answers while a scan holds the wallet.
- Returns:

```json
{
  "is_scanning": false,
  "cancel_requested": false,
  "start_height": 1,
  "scanned_height": 5,
  "tip_height": 5,
  "progress_pct": 100
}
```

  The heights describe the current or most recent scan (all 0 before the
  first). `scanned_height` is estimated from libwallet's percentage messages
  and reaches `tip_height` when the scan finishes. `progress_pct` is 0 to 100.
- Errors: `InvalidHandle`.

### `grin_wallet_scan_cancel(handle)`

- Takes no wallet lock. Returns nothing. See the limitation under
  `grin_wallet_scan`.
- Errors: `InvalidHandle`.

## 11. Test-only functions (`test-utils` feature)

Declared in the header only under `#ifdef GRIN_FFI_TEST_UTILS` and exported
only by builds with `--features test-utils`. Release artifacts export none.

### `grin_test_create_wallet(chain_dir, wallet_dir, client_id, network, mnemonic, password)`

- Starts (on first use per `chain_dir`) an in-process chain at
  AutomatedTesting (coinbase maturity 3) with a wallet proxy thread, then
  creates the wallet in `<wallet_dir>/wallet_data`, or opens it if
  `wallet.seed` exists (the mnemonic is then ignored), connected to that chain
  as `client_id`.
- `client_id`: non-empty, unique per chain, not `"node"`. Reusing an id
  re-attaches that wallet. `mnemonic` nullable as in `grin_wallet_create`.
- Takes the same directory guard as `grin_wallet_open`. The handle works with
  every handle function.
- Every `network` is accepted so tests can check keychains and address
  prefixes, but the chain is always AutomatedTesting; funded flows should use
  `network` 3.
- Returns `{"handle": u64}`.

### `grin_test_mine_blocks(handle, count)`

- Mines `count` blocks whose coinbase pays the wallet behind `handle`.
- Returns `{"height": u64}` (chain height afterwards).
- Errors: `InvalidHandle`, `InvalidArgument` (not a test wallet).

### `grin_test_panic()`

- Always fails with `InternalPanic` and message `"grin_test_panic"`.
